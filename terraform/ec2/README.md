# Deploying to EC2 with Terraform

This provisions one EC2 instance that clones `devops-sentinel` from GitHub
and runs it with `docker compose up --build`. It deploys the core app
(mongo, backend, frontend) only — independent from `../main.tf` (EKS),
which is a separate, unfinished configuration.

## Prerequisites

- AWS CLI configured with a working IAM user (see root `deploy/README.md`
  section 1 for creating one with least-privilege EC2 permissions).
- Terraform >= 1.8.0.
- The GitHub repo must be **public** (the instance clones over plain HTTPS
  with no credentials). If you need it private instead, add a
  `github_token` variable and use
  `https://${var.github_token}@github.com/...` as the clone URL in
  `user_data.sh.tpl` — ask for this variant if you switch visibility later.

## 1. Install Terraform (if not already installed)

```bash
winget install Hashicorp.Terraform
```

## 2. Configure variables

```bash
cd terraform/ec2
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars`:

| Variable | What to set |
|---|---|
| `allowed_ssh_cidr` | Your IP + `/32`. Get it with `curl -s https://checkip.amazonaws.com` |
| `github_repo_url` | `https://github.com/<you>/devops-sentinel.git` |
| `mongo_root_password` | A strong random value — generate with `openssl rand -base64 24` |

`terraform.tfvars` is gitignored — it never goes to GitHub.

## 3. Apply

```bash
terraform init
terraform plan    # review what will be created
terraform apply   # type "yes" to confirm
```

This creates: one SSH key pair (generated by Terraform), one security
group (port 22 from your IP, port 80 from anywhere), and one EC2 instance
that installs Docker, clones the repo, writes the production `.env`, and
runs `docker compose up -d --build` automatically on first boot.

The initial build takes 3-5 minutes (npm/go/vite builds happen on the
instance itself). Watch progress:

```bash
PUBLIC_IP=$(terraform output -raw public_ip)
terraform output -raw ssh_private_key > sentinel-deploy-key.pem
chmod 400 sentinel-deploy-key.pem

ssh -i sentinel-deploy-key.pem ec2-user@$PUBLIC_IP \
  "tail -f /var/log/cloud-init-output.log"
# Ctrl-C once you see the containers start.
```

## 4. Verify

```bash
curl -s http://$(terraform output -raw public_ip)/health
```

## 5. Wire up automated deploy-on-push (CD)

```bash
cd ../..   # repo root
gh secret set EC2_HOST --body "$(cd terraform/ec2 && terraform output -raw public_ip)"
gh secret set EC2_USER --body "ec2-user"
gh secret set EC2_SSH_KEY < terraform/ec2/sentinel-deploy-key.pem
```

From here, every push to `main` that passes CI automatically SSHes in,
`git pull`s, and rebuilds the containers (see the `deploy` job in
`.github/workflows/ci.yml`).

## Updating the instance's own config

If you change `mongo_root_password`, `instance_type`, or `github_repo_url`
in `terraform.tfvars`, re-run `terraform apply` — it will replace the
instance and its user-data re-runs from scratch (this wipes the Mongo
data volume, since it's a fresh instance). For routine app updates, let
the CD pipeline handle it instead (section 5) — that only updates the code
in place.

## Rollback / cleanup

```bash
# Stop the app, keep the instance
ssh -i sentinel-deploy-key.pem ec2-user@$PUBLIC_IP \
  "cd /opt/devops-sentinel && docker compose down"

# Destroy everything Terraform created (instance, key pair, security group)
terraform destroy
```
